# 06 · 方位计算与数据表

> 本文件是第四步「以当前城市为太极点」的技术依据。
>
> 核心主张：**方位必须算，不能凭感觉。** "成都在上海西边"这种判断人脑大致能出，但"成都是西还是西南""北京是西北还是北"就必须算——差 3 度就换一个五行。

---

## 一、为什么方位要算

| 靠感觉 | 靠计算 |
| --- | --- |
| 只看地图上的相对位置 | 用经纬度算大圆方位角 |
| 边界地带必错（如上海→北京 336°，是西北不是北） | 明确给出角度与扇区 |
| 无法复核 | 任何人都能重算验证 |
| 容易被"我觉得偏南一点"带偏 | 结果唯一 |

**方位是本技能唯一"可以做到确定"的一环。** 喜用判断有争议、地域五行依据不足，但方位角是几何事实。所以这一环必须做扎实。

## 二、算法

### 2.1 大圆初始方位角

```
θ = atan2( sin Δλ · cos φ₂ ,  cos φ₁ · sin φ₂ − sin φ₁ · cos φ₂ · cos Δλ )
```

- φ₁, λ₁ = 原点纬度、经度（弧度）
- φ₂, λ₂ = 目标纬度、经度
- Δλ = λ₂ − λ₁
- 结果转回角度并归一化到 0–360（0° = 正北，90° = 正东，顺时针）

### 2.2 球面距离（haversine）

```
a = sin²(Δφ/2) + cos φ₁ · cos φ₂ · sin²(Δλ/2)
d = 2R · asin(√a)　　　R = 6371.0088 km
```

### 2.3 已知局限（必须知道）

| 局限 | 影响 | 处理 |
| --- | --- | --- |
| 给的是**初始**方位角，不是全程恒定方位 | 超远距离（如上海→伦敦）中途方位会变 | 报告可注明"以出发时的初始方位为准" |
| 球面模型，非椭球 | 误差 < 0.5% | 对 45° 扇区判定无影响 |
| 坐标取市中心 | 都会区跨度可达 50 km | 边界 ±3° 内时提示"归属不稳" |
| 跨 180° 经线 | 公式本身正确（用 atan2 不会有问题） | 无需特殊处理 |
| 极区（|纬度| > 80°） | 方位意义弱化 | 提示"高纬地区方位判读不可靠" |

### 3.3 八方与二十四山冲突时

每个 45° 扇区含三个山，其中常有与八方五行不同的：

| 扇区 | 内含三山 | 冲突点 |
| --- | --- | --- |
| 北（水） | 子水、癸水、壬水 | 无 |
| 东北（土） | 丑土、艮土、**寅木** | 寅属木 |
| 东（木） | 甲木、卯木、乙木 | 无 |
| 东南（木） | 辰土、巽木、**巳火** | 辰属土、巳属火 |
| 南（火） | 丙火、午火、丁火 | 无 |
| 西南（土） | 未土、坤土、**申金** | 申属金 |
| 西（金） | 庚金、酉金、辛金 | 无 |
| 西北（金） | **戌土**、乾金、**亥水** | 戌属土、亥属水 |

**规则**：
1. **主判据用八方位**（有原文直证）
2. 二十四山写在括号里作参考
3. 两者不同行 → 标"**方位杂气**"，该方位的说服力降一档
4. **不许**因为某个山向更合命局，就改用二十四山判——那是凑结论

> 四个"纯方位"（正东纯木、正南纯火、正西纯金、正北纯水）在三山内五行一致，是最干净的推荐位。四维方位（东北/东南/西南/西北）天然杂气，推荐时要说明。

## 四、脚本用法

位置：`scripts/fangwei.py`　依赖：Python 3，仅标准库。

> 若 `python` 不在 PATH 上，用解释器绝对路径调用，例如
> `"C:/Users/Administrator/.workbuddy-ai/binaries/python/versions/3.13.12/python.exe" scripts/fangwei.py ...`
> 或先 `cd` 到 `scripts/` 目录再执行，避免相对路径找不到 `cities.json`。

```bash
# 【第四步首选】一条命令出城市卡：方位 + 州五行 + 两栏关系
python scripts/fangwei.py --from 上海 --to 成都 北京 昆明 --card

# 基本用法：表格形式，多一列"所属州（州五行）"和"两栏关系"
python scripts/fangwei.py --from 上海 --to 成都 深圳 北京 西安 杭州

# 单城州归属查询（含定/议/外档位与争议说明）
python scripts/fangwei.py --zhou 北京

# 单目标 + 直接给坐标（城市库没有的地方）
python scripts/fangwei.py --from 上海 --to-lat 30.57 --to-lon 104.07

# 原点也用坐标（如住在某县城）
python scripts/fangwei.py --from-lat 31.23 --from-lon 121.47 --to 成都

# 反查：已定喜用五行，问该往哪几个方位 + 哪几个州
python scripts/fangwei.py --want 木 火

# 输出 JSON（便于二次处理）
python scripts/fangwei.py --from 上海 --to 成都 --json

# 列出内置城市（会同时列出未登记州属的城市）
python scripts/fangwei.py --list
```

## 五、城市库

位置：`scripts/cities.json`，**3283 条（中国 3231 + 海外 52）**。州归属另存 `scripts/zhou.json`，逐条登记"定/议/外"三档 + 依据来源。

> **V2.0 变更**：从"227 座主要城市"扩为**全国地级市 + 县级行政区全覆盖**（2840 个县级 + 369 个地级/直辖 + 22 个台湾县市）。数据不再是手挑的，是从行政区划数据源批量生成并逐条登记州属。

### 5.1 结构

```json
{
  "_meta": { "版本": "V2.0…", "数据来源": "…", "重名处理": "…" },
  "中国": { "上海": [31.2317, 121.4726], "昆山": [31.3819, 120.9581], "北京朝阳": [39.9215, 116.4864] },
  "海外": { "东京": [35.6895, 139.6917] },
  "_alias":    { "江苏省南京市鼓楼区": "南京鼓楼", "北京市朝阳": "北京朝阳" },
  "_ambiguous": { "鼓楼": ["南京鼓楼", "开封鼓楼", "徐州鼓楼", "福州鼓楼"] }
}
```

数组为 `[纬度, 经度]`，WGS84，取**行政区中心点**（非市政府驻地）。

`zhou.json` 的每条记录：

```json
"南京鼓楼": {
  "州": ["扬州"], "档": "定", "源": "批量推演",
  "全名": "鼓楼区", "级": "district", "省": "江苏省", "市": "南京市"
}
```

`源` 只有两个值：**人工核定**（227 条，逐城核过）/ **批量推演**（3056 条，按规则推导）。

`级` 有四个值：`city`（地级市 / 直辖市 / 特别行政区，369 条）、`district`（区/县/县级市/旗，2840 条）、`county`（台湾县市，22 条）、`overseas`（境外 52 条）。台湾的「县」与「市」同为第一级行政区，统一用 `county` 与大陆县级区分，输出时显示为"台湾县市"。

### 5.2 数据来源与重建

| 项 | 内容 |
| --- | --- |
| 来源 | 阿里云 DataV.GeoAtlas `areas_v3/bound/<adcode>_full.json`，2026-10 抓取 |
| 层级 | 省 35 → 市/直辖市区 475 → 区县 2840 |
| 生成脚本 | `_src/geo/crawl.py`（抓取）、`_src/geo/build_full.py`（合成 + 州归属推导） |
| 重建方式 | 先跑 crawl.py 落 `_src/geo/areas.json`，再跑 build_full.py。**幂等**，可反复执行 |
| 行政口径 | 以国家统计局区划为准（DataV 数据源）；含港澳台，台湾 22 县市为人工补录 |

**为什么不手工维护**：3000 条手工会出错且无法复核。批量生成 + 明确标注"批量推演"，比手工挑 200 条然后假装覆盖全国更诚实。

### 5.3 重名消歧规则

全国有 118 组同名行政区（鼓楼区 4 个、城区 3 个、朝阳 3 个…）。规则：

| 情形 | 处理 | 例 |
| --- | --- | --- |
| 名字唯一 | 直接用本名 | 上海、成都、昆山 |
| 重名且其中一个是**地级市** | 市占本名，其余加市名前缀 | `西安`（市）/ `牡丹江西安`（区） |
| 重名且**同为县级** | 一律加市名前缀 | `南京鼓楼`、`徐州鼓楼`、`开封鼓楼`、`福州鼓楼` |
| 父名与本名相同 | 用全名区分 | `红河`（州）/ `红河县`；`大理`（州）/ `大理市` |

**查询行为**：直接写歧义名（如 `鼓楼`）**不会静默取一个**，而是列出全部候选并报错，要求写"市名+区名"。这是故意的——静默取一个比报错危险得多。

别名表 `_alias` 支持这些写法，都指向同一个键：`鼓楼区`、`南京市鼓楼区`、`江苏省南京市鼓楼区`、`南京鼓楼`。

### 5.4 精度

| 用途 | 所需精度 | 本库是否够 |
| --- | --- | --- |
| 45° 扇区判定 | ±0.5°（约 ±55 km） | ✅ 够（中心点精度约 ±0.02°） |
| 二十四山（15°）判定 | ±0.2° | ⚠️ 边界地带需复核 |
| 距离估算 | 两位数 | ✅ 够 |

> 落在扇区边界 3° 内时脚本会提示，此时应回查坐标而不是硬用。**中心点是几何中心，不是市政府驻地**，两者可能差几公里——对 45° 扇区无影响，对精细山向有影响。

### 5.5 覆盖范围与粒度边界

**覆盖到哪一层：**

| 层级 | 数量 | 覆盖 |
| --- | --- | --- |
| 省级 | 34 | ✅ 全 |
| 地级市 / 直辖市区 | 375 | ✅ 全 |
| 县级行政区（区/县/县级市/旗） | 2840 | ✅ 全 |
| 台湾 | 22 县市 | 数据源无台湾下级区划，22 个县市人工补录（含金门、连江）；台北等 6 座人工核定，余 16 座批量推演 |
| 海外 | 52 座 | ⚠️ 主要目的地，非全量 |

**三条粒度边界，必须知道：**

1. **同城内部的区，现在能算了，但要说清算法。** V2.0 起北京海淀、上海浦东都是独立条目，可以算。但这是**行政区中心点之间的方位**，不是"区内某条街"的方位。用户问"同城搬哪个区"，可以说方向，但必须说明这是区中心之间的相对方位，**精度只到区，不到街道**。
2. **县级市/县按自己的坐标算方位，按所属市继承州归属。** 例如昆山→上海 51.7 km，脚本判"同城/近邻"，这是对的：昆山与上海在择城尺度上不是两个"远方"。
3. **"距离不足 50 km 视为同城"是硬规则**，不做例外。这个阈值来自"择城"这个问题的尺度——同城通勤不叫迁居。

## 六、常见坑

| # | 坑 | 后果 | 处理 |
| --- | --- | --- | --- |
| 1 | 只看"大致方向" | 边界地带判错扇区 | 必须跑脚本 |
| 2 | 忽略距离 | 50 km 内的"方位"毫无意义 | 脚本自动提示"同城" |
| 3 | 用省份中心代替城市 | 偏差可达 200 km | 逐城取坐标 |
| 4 | 港澳台按"境外"处理 | 错误 | 均属中国，按扬州等州处理；台湾城市标"议"（九州之外/扬州域外两说并列） |
| 5 | 境外城市套用九州分野 | 无依据 | 只用丙级地理取象，明写"缺古籍依据" |
| 6 | 换城市后忘了换太极点 | 整份方位全错 | 太极点只有一个：用户当前长期居住地 |
| 7 | 两地生活却只取一个原点 | 方位失真 | 请用户说明，必要时做两套 |
| 8 | 边界 ±3° 内不给提示 | 结论看起来确定，实际不稳 | 脚本已内置提示，报告要如实转述 |

## 七、这一环与地域五行的分工

| | 方位（本文件） | 地域五行（03 号文件） |
| --- | --- | --- |
| 性质 | 相对几何 | 绝对属性 |
| 依据 | 经纬度 + 八卦配五行原文（甲） | 州五行（甲）+ 州→城市归属（乙）+ 地理取象（丙） |
| 置信 | **高** | 中（州五行甲级，落到城市降乙级） |
| 变化 | 换个城市就变 | 不随你变 |
| 报告位置 | 第四段"方位"栏 | 第四段"地域"栏 |

**永远分两栏写。** 一栏写"相对你现在的位置，这城在西边，属金"，另一栏写"这城本身的地域属性偏 __，依据 __ 级"。两栏结论可以相反，不许为了好看而合并。

### 7.1 两套系统在多个方位上直接相反（V1.2 新增，V1.3 精确化）

接入《三命通会》卷四州五行之后，方位五行与州五行会正面冲突：

| 方位 | 八卦方位五行 | 该方位的州 → 州五行 | 结果 |
| --- | --- | --- | --- |
| 东南 | 木（巽） | 徐 → 火 | ❌ 硬冲突 |
| 西南 | 土（坤） | 梁 → 金 | ❌ 硬冲突 |
| 西北 | 金（乾） | 雍 → 水 | ❌ 硬冲突 |
| 正南 | 火（离） | 扬 → 火 / 荆 → 金 | ⚠ 半冲突（扬同向、荆相反） |
| 东北 | 土（艮） | 冀 → 水 | ⚠ 半冲突（方位含冀州一角） |
| 正东 | 木 | 青/兖 → 木 | ✅ 同向 |
| 正北 | 水 | 冀 → 水 | ✅ 同向 |
| 中央 | 土 | 豫 → 土 | ✅ 同向 |

**严格说：硬冲突三处（东南、西南、西北），半冲突两处（正南、东北）。** 但落到具体城市时不用记这张表——跑 `fangwei.py` 的"两栏关系"列会直接告诉你这个城市是同向还是相反。

**所以：跑完本文件算出方位五行之后，不许拿它去"验证"州五行。** 两者本来就是两套东西——一个回答"朝哪走"，一个回答"那地方是什么气"。冲突时并列，说明这是两套系统的分歧。

推导与处理规则见 `03-城市地域五行规则.md` §9.4，原文依据见 `03a-三命通会分野规则.md` §3。
